# E42 · L2 goal state 上的 Lean hammer 扫描（2026-11-08）

## 一句话

在 283 个真实 goal state 上挂 9 支 Lean 自带自动化战术，只找到 **7 个可闭合点**；
其中真正属于「模型写不下去、工具接手」的只有 **1 道题（q11，3–4 步前缀后由 `aesop`/`simp_all` 收尾）**。
**这条路不值得再投。** 同时量出一个更关键的事实：**49% 的 goal state 根本不存在**——
它们的前缀在 Lean 里是非法代码，探针却把这些步记成了 `UNSOLVED`。

---

## 为什么做这个

E41 量出噪声底：同代码 / 同机 / 同日 / `temp=0` 重跑，pass 2/18→1/18、步 1 tactic 只有 8/18 相同。
⇒ n=18 的题级 A/B 无鉴别力。所以改做**确定性、零 LLM 配额、无随机性**的测量：
不比较两臂，只问「把 Lean 自带 hammer 挂在每一步，能不能闭合」。

## 协议

- 数据：三臂 `b_fix`(11-07) / `base2` / `rej`(11-08) 共 54 条轨迹、354 步；
  按 `(formal_sig, 已生效 tactic 前缀)` 去重 ⇒ **283 个扫描点**，覆盖全部 18 题。
- 每个点生成 `example ... := by <前缀> <hammer>`，hammer 9 支：
  `omega / nlinarith / linarith / simp_all / norm_num / positivity / ring_nf / exact? / aesop`。
- 逐字复刻探针 `build_code`（**不关 autoImplicit**，E39 只改门A 编译，主编译口径不变）。
- 每条 example 后跟 `#eval "MARK_<idx>"` 哨兵，确认该条确实被解析执行。
- 对照文件 `V_base`（前缀 + 模型原 tactic）与 `V_prefix`（**只含前缀**）验证重建口径。
  ★ **可信判据必须用 `V_prefix`**：`V_base` 的硬错误可能来自模型本步 tactic 而非前缀，
  用它剔除会过严（28 个点因此被误剔，见下）。
- 闭合判据：哨兵出现 + 归属区间内零 error + 无 `declaration uses 'sorry'`。
- **独立复现**：所有判为 CLOSED 的点各生成一个单文件重编译，以 `rc=0` 为准。

## 三个附带发现（比主结论更值钱）

### ① 探针的 `compile_check` 会掩盖硬错误

`l2_step_probe.py::compile_check` 的判定顺序是「raw 里出现 `unsolved goals` ⇒ 返回 `UNSOLVED`」。
于是**同时存在语法/类型/未定义常量错误**的代码也被当成合法步骤继续跑，
导致 139/283 个扫描点的前缀其实编译不过。这是继 EMPTY 谎报之后，L2 探针的第二个协议缺陷。

**但主因不在我们**：对 144 个坏前缀做「多行 tactic 每行统一 +2 空格」的缩进修复对照，
只有 **6 个（4.2%）** 转为合法 ⇒ `build_code` 的多行缩进 bug 只是小头；
绝大多数是模型自己写出非法 Lean（`unknown constant`、逗号分隔 tactic、`numerals are data`、
`have ... := by` 后缩进散架、`Type mismatch`）。**能力边界在模型侧，不在管道侧。**

### ② 两个解析/环境坑（已写进脚本注释）

- Lean 4.31 的错误有两种格式：`error: ...` 和 **`error(lean.unknownIdentifier): ...`**。
  解析器只认前者会漏掉约 8% 的错误，直接制造**假闭合**（首轮解析曾误报 q24 多个闭合点）。
- 文件内 `set_option maxErrors N` **完全无效**（硬上限 100，第 100 个 error 直接 exiting）。
  必须用命令行 **`lean -DmaxErrors=10000`**；实测 150 条必然报错的 example 可全部跑完。

### ③ `exact?` 不是闭合战术

它只打印 `Try this: ...` 建议，目标仍开着。修正解析后它的"闭合"只剩 1 个整题基线真闭合，
其余均为假阳性。若将来要利用它，得解析建议文本再回填编译，本轮未做。

## 不宣称 / 边界

- **不宣称效果量**：这是「存在性构造」，不是 A/B。构造依赖模型随机写出的前缀，
  14 个闭合点跨三臂，不能换算成通过率提升；n=18 仍在 E41 噪声底内。
- **不宣称忠实**：`rc=0` 只说明 Lean 接受了这个证明，不说明命题忠实于原题
  （门A 的 `False` 骨架、空真/恒假盲区仍在，见 E40）。q24 尤其未做语义核验。
- **不宣称「其余 16 题 hammer 一定救不动」**：139 个点因前缀非法被剔除，
  它们从未被真正测过；且只用了 9 支内置战术、单步追加，没有搜索、没有引理注入。
- **不改生产代码、不动 POLICY 101 项、无回归可跑**（本轮全是仓库内探针产物）。

## 下一步判断

再加层（更多 hammer / 更长 tactic 序列 / 提示词）边际收益为 0：
工具侧只在 1 道题上产生真实增量，而 49% 的失败来自模型写不出合法 Lean。
**要么换专用 prover 模型作为工具接入，要么把资源转到命题级忠实度**；
继续在判定链或扫描战术上堆料已被 E28→E39→E40→E42 四次印证为无效。
