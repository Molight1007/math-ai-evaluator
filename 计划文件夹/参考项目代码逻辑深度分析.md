## <a id="1"></a>一、确定性工具优先求解

> 来源：`challeng_final_submit-main/src/math_agent/`

### 1.1 为什么需要这个机制？

当前 MathPilot 的 Solver 对每道题都要调用 LLM。但实际上很多数学题（如求导、积分、解方程、行列式计算、排列组合）可以用 SymPy 或纯 Python **零成本、零幻觉**地求出正确答案。

**对比**：
- LLM 求解：消耗 token，花费时间（几秒到几十秒），可能产生幻觉
- 确定性工具：免费，毫秒级，结果绝对可靠

### 1.2 完整流程图

```
题目输入
  │
  ├─[步骤0] 资源限制检查 tool_input_within_resource_limits()
  │     ├─ 检查数字不超过 32 位 / 10^12
  │     ├─ 组合数学题 n ≤ 500
  │     ├─ 数论题整数 ≤ 10^9
  │     └─ 不通过 → 跳过确定性求解，走 LLM 管线
  │
  ├─[步骤1] solve_deterministically() — 15 个 handler 按优先级依次尝试
  │     ├─ 1. 微分方程（ODE）→ SymPy dsolve
  │     ├─ 2. 偏微分方程（PDE）→ 特征线法
  │     ├─ 3. 多元微积分 → 偏导/梯度/二重积分/拉格朗日乘数
  │     ├─ 4. 单变量微积分 → 求导/积分/极限/切线
  │     ├─ 5. 线性代数 → 矩阵运算/行列式/特征值/方程组
  │     ├─ 6. 运筹学 → 0-1背包/线性规划/最短路径
  │     ├─ 7. 概率统计 → 均值/方差/二项概率/贝叶斯
  │     ├─ 8. 组合数学 → C(n,k)/P(n,k)/容斥原理
  │     ├─ 9. 数论 → GCD/LCM/模逆/欧拉φ/中国剩余定理
  │     ├─ 10. 图论 → 握手引理/树的边数/欧拉公式
  │     ├─ 11. 复分析 → 复数运算/模辐角/De Moivre
  │     ├─ 12. 解析几何 → 直线方程/距离公式
  │     ├─ 13. 几何 → 三角形面积/海伦公式/勾股定理
  │     ├─ 14. 分析/拓扑 → 序列极限/级数收敛/开闭集
  │     └─ 15. 代数 → 方程/多项式/不等式/绝对值（兜底）
  │
  ├─[步骤2] 如果步骤1未命中 → _run_tool_assist 第二阶段
  │     ├─ 宽松正则匹配自然语言（"derivative of f(x)=..." ）
  │     └─ 纯算术表达式安全求值 _eval_safe_math_expr
  │
  ├─[步骤3] 命中 → 直接输出答案，不调用 LLM
  │     └─ 包装为 "\boxed{答案}"
  │
  └─[步骤4] 全部未命中 → 走标准 LLM 管线（Planner → Solver → Verifier）
```

### 1.3 核心设计思想

**为什么不是"先分类再选handler"而是"让15个handler依次尝试"？**

因为 LLM 对问题类型的分类可能出错（如把线性代数题误判为微分方程），但如果让每个 handler 用正则表达式检查题目是否匹配自己的模式，命中率是 100% 的——正则匹配天然精确。那 15 个 handler 的遍历速度很快（毫秒级），且顺序有讲究：

- **ODE/PDE 放在最前面**：关键词（`dy/dx`、`u_xx`）非常独特，不会与其他类型混淆
- **代数题放在最后**：作为"兜底"，代数题的匹配模式最宽泛

### 1.4 关键算法细节

#### 资源限制检查的设计哲学

在运行任何计算之前，先扫描题目中的数字字面量：
- 数字字符串长度不超过 32 位
- 绝对值不超过 10^12
- 组合数学题中整数不超过 500（防止 C(1000,500) 计算量爆炸）
- 数论题中整数不超过 10^9

这是一种**防御性编程**：防止超大数字导致 SymPy 或 Python 耗尽内存。

#### 安全表达式求值器 `_eval_safe_math_expr`

**不用 `eval()`**，而是用 `ast.parse` 手动递归遍历 AST 节点，只允许白名单操作符：
- 二元：+, -, *, /, **
- 一元：+, -
- 限制：AST 节点数 ≤ 128、深度 ≤ 32、整数位数 ≤ 4096 bit、指数 ≤ 128

#### 异常容错设计

每个 handler 内部用 try-except 包裹所有 SymPy 异常类型（`ArithmeticError, TypeError, ValueError, SyntaxError, TokenError, NotImplementedError, SympifyError`），异常只是 `continue` 到下一个 handler，不会中断整个流程。

### 1.5 在 MathPilot 中的集成方案

**推荐方案：在 `orchestrator.py` 的求解管线最前面插入"确定性快速通道"**

```python
def solve(question, ...):
    # 新增：确定性快速通道
    if tool_input_within_resource_limits(question):
        result = solve_deterministically(question)  # 15 handler 尝试
        if result:
            return wrap_as_final_answer(result)     # 直接返回，不走 LLM
    
    # 原有：LLM Agent 管线
    return run_llm_pipeline(question, ...)
```

**核心改动点**：
1. 新建 `submit/agent/tools/deterministic.py`，移植 15 个 handler 和正则匹配
2. 在 `orchestrator.py` 的 Solver 调用之前插入拦截逻辑
3. 确定性结果需要包装成与 LLM 输出一致的格式

**预期收益**：对于结构明确的数学计算题（如求导、积分、行列式），可以节省 80% 以上的 LLM 调用，且准确率提升。

## <a id="2"></a>二、温度分层 + 多候选投票 + 难度自适应

> 来源：`ss-main/agents/`

### 2.1 整体流程

```
题目输入
  │
  ├─ 规则分类器 rule_classify() — 零成本分析题目领域和难度
  │     └─ 输出: {subject, problem_type, difficulty}
  │
  ├─ 难度 → 候选数映射
  │     ├─ easy → 1 候选
  │     ├─ medium → 2 候选
  │     └─ hard → 3 候选
  │
  ├─ 专项 Prompt 路由
  │     ├─ proof → 证明题专用 prompt
  │     ├─ choice → 选择题专用 prompt
  │     ├─ algebra / analysis / probability / combinatorics / optimization
  │     └─ default → 通用 prompt
  │
  ├─ 温度分层生成候选
  │     ├─ candidate_1: temperature=0.1（最保守：走"最可能对"的路径）
  │     ├─ candidate_2: temperature=0.3（中等随机性）
  │     └─ candidate_3: temperature=0.5（高随机性：探索不同路径）
  │
  ├─ 投票选出最佳候选
  │     ├─ 1. 答案规范化 normalize_for_vote()
  │     ├─ 2. 等价分组 group_equivalent_answers()
  │     │     └─ SymPy 判断 simplify(a-b)==0 → 归入同一组
  │     ├─ 3. 多数派投票 majority_vote() → 选最大组
  │     └─ 4. 六维评分 score_candidate()
  │
  ├─ LLM 结构化验证（只验证第一名，节省算力）
  │     ├─ 要求 LLM 输出: 正确性 / 问题 / 修正答案 / 置信度
  │     └─ 分数微调: correct→+0.15, wrong→-0.25, uncertain→-0.05
  │
  └─ 输出 + 是否需要修正标记
```

### 2.2 核心机制详解

#### 机制A：温度分层

**目的**：同质化是对多候选最大的浪费。如果三个候选使用相同温度，它们容易给出相似的推理路径和答案。

**实现**：
```python
CANDIDATE_TEMPERATURES = (0.1, 0.3, 0.5)  # 硬编码三元组
```
- 温度 0.1（最保守）：模型走"最可能正确"的路径，适合标准解法
- 温度 0.3（中等）：在确定性路径的周围小范围探索
- 温度 0.5（较高）：鼓励模型不走常规路线，可能发现创新解法

**关键点**：温度值是按索引一一映射的（候选1→0.1，候选2→0.3，候选3→0.5），而非随机分配。这保证了可复现性——同一道题每次运行，候选1永远是温度0.1的结果。

#### 机制B：难度自适应候选数

**分类方法**：纯规则引擎（零 LLM 成本）

```python
if "证明" in text or "prove" in text or "抽象" in text:
    difficulty = "hard"
elif "计算" in text or "求" in text or "evaluate" in text:
    difficulty = "easy"
else:
    difficulty = "medium"  # 默认
```

**映射**：
```python
DIFFICULTY_COUNTS = {"easy": 1, "medium": 2, "hard": 3}
```

**设计意图**：简单计算题不需要多个候选（浪费算力），困难证明/抽象题需要多个候选来交叉验证。这不是用 LLM 分类的，而是基于题面关键词的快速规则——零额外成本。

#### 机制C：多候选投票

**步骤1：答案规范化** `normalize_for_vote()`
```
原始答案 → 去markdown包裹 → 提取\boxed{} → 去$ → 去前缀 → 合并空白
```

**步骤2：等价分组** `group_equivalent_answers()`
遍历每个候选的规范化答案：
- 两个空答案 → 归入同一组（精确匹配）
- 两个答案都非空 → 用 `are_answers_equivalent()` 判断
  - 第1层：字符串精确比较
  - 第2层：LaTeX 分数标准化后比较（`\frac{a}{b}` → `(a)/(b)`）
  - 第3层：**SymPy 符号等价**（`simplify(a-b) == 0`，最强大）
  - 第4层：无法解析 → 判定不等价

**步骤3：六维评分** `score_candidate()`

| 维度 | 加减分 | 条件 |
|------|--------|------|
| 有答案 | +0.25 | answer 非空 |
| 无答案 | -0.50 | answer 为空 |
| 有解题过程 | +0.15 | solution 非空 |
| 无解题过程 | -0.20 | solution 为空 |
| 多数派 | +0.25 | 属于最大等价组 |
| 多数派 ≥2人 | +0.05 | 组人数 ≥ 2 |
| 无不确定用语 | +0.15 | 不含"不知道/无法回答/不会" |
| 有不确定用语 | -0.30 | 含不确定标记 |
| 置信度加成 | +conf×0.1 | 候选有自信度字段 |
| 短答案加成 | +0.02 | 规范化答案 ≤20 字符 |

**理论满分**：0.25+0.15+0.25+0.05+0.15+0.1+0.02 = **0.97**

**排序规则**：按 `(得分, 票数, -答案长度)` 降序。即得分高优先→票数多优先→答案短优先。

#### 机制D：LLM 结构化验证（分数微调）

**为什么只验证第一名？** 成本控制。如果 3 个候选都要 LLM 验证，要多调用 3 次 API。

**验证 Prompt 要求 LLM 输出固定格式**：
```
正确性：correct / wrong / uncertain
问题：
修正答案：
置信度：
```

**分数微调公式**：

| LLM 判定 | 调整公式 | 效果 |
|----------|----------|------|
| correct | score = clamp(score + 0.15 × confidence) | 微加分 |
| wrong | score = clamp(score - 0.25 × confidence) | 大幅扣分 + 用修正答案替换 |
| uncertain | score = clamp(score - 0.05) | 轻微惩罚 |

**设计哲学**："do not overturn voting selection identity" —— LLM 验证只做**微调**，不推翻投票选择。

### 2.3 在 MathPilot 中的集成

**可复用的核心模块**：
| 模块 | 实现难度 | 收益 |
|------|---------|------|
| 温度分层 | 低 | 中（增加候选多样性） |
| 难度自适应候选数 | 低 | 中（节省 LLM 调用） |
| 等价分组投票 | 中 | **高**（纯规则，零成本，直接提升选答案准确率） |
| LLM 结构化验证 | 中 | 中高（增加一层独立验证） |
| 专项 Prompt 路由 | 中 | 中（需要按题型定制 prompt） |

## <a id="3"></a>三、答案处理完整管线

> 来源：`challeng_final_submit-main/src/math_agent/`

### 3.1 答案规范化管道 `normalize_answer()`

**7 步处理流程**：

```
原始答案文本
  │
  ├─ 1. 答案提取
  │     ├─ 优先从 \boxed{} 提取（取最后一个 boxed）
  │     └─ 无 boxed → 匹配中英文关键词：最终答案/答案是/解为/解得/所以
  │
  ├─ 2. 单位剥离 strip_units()
  │     └─ 去除：cm, mm, m, km, kg, g, s, celsius, dollars, %
  │
  ├─ 3. LaTeX 规范化 normalize_latex()
  │     ├─ \frac{a}{b} → a/b
  │     ├─ \sqrt{x} → sqrt(x)
  │     ├─ \cdot / \times → *
  │     ├─ \pi / π → pi
  │     ├─ \left / \right 删除
  │     └─ \text{...} / \mathrm{...} → 纯文本
  │
  ├─ 4. 数学间距压缩 _compact_math_spacing()
  │     └─ "3 + 4" → "3+4"（但保留自然语言句子的空格）
  │
  ├─ 5. 隐式乘法插入 _insert_implicit_multiplication()
  │     ├─ "2pi" → "2*pi"
  │     ├─ "3x" → "3*x"
  │     ├─ ")x" → ")*x"
  │     ├─ "2(" → "2*("
  │     └─ ")(" → ")*("
  │
  ├─ 6. 数值规范化 normalize_number()
  │     ├─ "1,234,567.89" → "1234567.89"（去千位分隔符）
  │     ├─ "5.0" → "5"（去无意义 .0）
  │     └─ "1*pi" → "pi"
  │
  └─ 7. 最终清理：大小写统一、yes/no 归一化
```

这个管道使得两个数学上等价但格式不同的答案能被识别为相同。如 `\frac{1}{2}` 和 `0.5` 经过处理后都变为结构化的表达式，可以在后续的符号匹配中被 SymPy 判定为等价。

### 3.2 答案匹配策略（judge.py）

**分层递进的 9 层匹配**：

| 层级 | 策略 | 条件 | 说明 |
|------|------|------|------|
| 1 | 超长拒绝 | 答案 >512 字符 | 直接判不等 |
| 2 | 归一化匹配 | normalize 后字符串相等 | 最快，命中率高 |
| 3 | yes/no 精确比较 | 大小写不敏感 | 判断题专用 |
| 4 | 数值匹配 | math.isclose(rel=1e-9) | 浮点数比较 |
| 5 | 符号匹配 | simplify(pred-gold)==0 | SymPy 符号等价 |
| 6 | 语义匹配 | SymPy + 高精度数值 | LaTeX→SymPy 转换后比较 |
| 7 | 序列匹配 | 无序/有序序列逐项匹配 | 多根、方程组、特征值 |
| 8 | 矩阵匹配 | 逐行逐列符号匹配 | 矩阵答案 |
| 9 | 关系式匹配 | 移项后比较残差 | 方程、圆锥曲线 |

**按 problem_type 路由**：

```
unordered_sequence → 无序序列匹配（根、特征值等）
ordered_sequence   → 有序序列匹配（梯度、叉积等）  
assignment_sequence → 赋值序列匹配（x=1, y=2）
matrix             → 矩阵匹配
ode                → ODE 语义匹配
relation           → 关系式匹配
default            → 标量语义匹配（兜底）
```

### 3.3 证明题特殊处理

**核心思想**：证明题没有 `\boxed{}`，答案在推理链的结论中。

**检测依据**：
- 中英文关键词：证明、试证、prove、show that、verify that
- 或 `problem_type == "proof"`

**从推理链提取结论**：
1. 拼接所有 `visible_solution_steps`（解题步骤）
2. 从中匹配结论句（"所以...""因此..."等）
3. 找不到则填 "命题已完成证明。"

**证明结构 12 维评分**：

| 特征 | 加分 | 说明 |
|------|------|------|
| 假设声明 | +0.12 | 设/已知/given/assume |
| 推理链 | +0.22+0.03×N | 因此/所以/hence/therefore |
| 结论 | +0.16 | 证毕/QED/已证 |
| 命题声明 | +0.08 | 有明确的待证命题 |
| 数学符号 | +0.05 | 使用了数学符号和公式 |
| 量词 | +0.04 | ∀/∃/任意/存在 |
| 分类讨论 | +0.05 | 有分情况讨论 |
| 归纳法 | +0.08 | 使用了数学归纳法 |
| 反证法 | +0.06 | 使用了反证法/矛盾法 |
| 长度 | +0.06 | ≥3 个句子 |
| 循环论证 | -0.45 | assume...to prove 同时 therefore...assume |
| 空洞断言 | -0.05 | 没有推理过程的断言 |

### 3.4 脏答案检测 `detect_dirty_final_answer()`

| 标志 | 含义 | 检测条件 |
|------|------|----------|
| `missing_final` | 缺失 final_answer | 字段为空 |
| `empty_value` | 值为空 | value 为 "" |
| `markdown_in_final` | 答案里有 markdown | 含代码块/多行/超长/"步骤一" |
| `dirty_boxed` | boxed 被污染 | boxed 内容含 markdown/长文本 |
| `boxed_42_fallback` | **42 幻觉** | boxed 恰好是 "42"（LLM 常见兜底幻觉） |
| `suspicious_short` | 可疑短答案 | value 为空或 "42" |

**修复流程**：
1. 从 `visible_solution_steps` 中重新搜索 `\boxed{}`
2. 如果 boxed 为空但 value 有效，自动包装为 `\boxed{value}`
3. 证明题走专属路径（清空 boxed，提取结论）

### 3.5 在 MathPilot 中的应用

| MathPilot 文件 | 可借鉴内容 | 收益 |
|----------------|-----------|------|
| `extract.py` | 多层答案提取 + LaTeX 规范化管道 | 更准确的答案抽取 |
| `verifier.py` | 9 层分层匹配策略 | 更准确的答案判定 |
| `verifier.py` | 证明题专项处理 + 12维评分 | 新能力：证明题评测 |
| `verifier.py` | 脏答案检测（特别是 42 幻觉） | 防止静默错误 |

## <a id="4"></a>四、ReAct代码执行 + ICMA交叉验证

> 来源：`MathRouterAgent-main/` + `ICMA-main/`

### 4.1 ReAct 代码即推理循环

**核心思想**：不让模型在"脑内"推演数学，而是强制它交替进行**思考→写代码→执行→观察**。

**ReAct 循环的 5 个关键安全机制**：

#### 机制A：Wall-Clock 超时 + 最优答案回溯

**问题**：如果模型陷入无限循环或卡住，不能无限等。

**实现**：
```
每个循环开头：elapsed = time.monotonic() - start_time
if elapsed > timeout:  # 默认 600s
    # 优雅恢复：
    for msg in reversed(trace):  # 反向遍历
        if msg.role == "assistant" and "\boxed{" in msg.content:
            return msg.content  # 找到最近一条带 boxed 的历史答案
    # 兜底：LLM 快速回答
    ask_llm("Based on the reasoning so far, give best \boxed{} answer.")
    # 终极兜底：
    return "\boxed{}"  # 空答案
```

**关键设计**：回溯的是"历史最优"而非"最后一条"。因为模型在超时前可能在尝试越来越错误的方法。

#### 机制B：截断代码恢复

**问题**：当 `max_tokens` 在代码中间截断（如 `coeffs = [1, 1, 2, 3, `），代码无法执行。

**实现**：
```python
# 从末尾逐行删除，找到第一个语法合法的最长前缀
for i in range(len(lines) - 1, 0, -1):
    try:
        ast.parse("\n".join(lines[:i]))
        return prefix + "\nprint('[truncated — partial output]')"
    except SyntaxError:
        continue
```

**关键点**：只做**语法完整性**恢复，不做语义补全。丢失的语义信息通过截断提示让模型下一轮调整策略。

#### 机制C：幻觉检测

**问题**：模型可能跳过 `<tool_call>`，直接写出 ` ```output ` 来"伪造"执行结果。

**实现**：
```python
if "```output" in out and "<tool_call>" not in out:
    # 检测到幻觉！
    # 注入 CRITICAL 警告：
    messages.append({
        "role": "user",
        "content": "CRITICAL: You simulated ```output. This is NOT real execution. 
                     You MUST emit <tool_call>...</tool_call> to get REAL results."
    })
```

#### 机制D：上下文裁剪

**问题**：长对话可能超过模型上下文窗口，导致 INPUT_LENGTH_ERROR。

**实现**（`MAX_MESSAGES = 22`）：
```python
if len(messages) > 22:
    messages = (
        messages[:2] +              # system + 第一题消息（不可丢）
        [summary_msg] +             # "[Earlier steps trimmed. Do NOT repeat.]"
        messages[-20:]              # 最近 20 条（约 5 步交互）
    )
```

**摘要消息包含策略指令**："Do NOT repeat earlier approaches — switch strategy if stuck"，防止模型在丢失上下文后陷入循环。

### 4.2 ICMA 答案契约检查

**核心思想**：有些题目的答案格式是"有结构的"——比如假设检验必须包含"拒绝/不拒绝"的结论，置信区间必须是 `[a, b]` 的双端形式。

**支持的 6 种契约**：

| 契约 | 触发题面特征 | 必须包含 |
|------|-------------|----------|
| 假设检验 | "检验"+"H_0"+"显著性水平"+"α" | "拒绝"/"不拒绝" |
| 置信区间 | "置信区间"且不含"单侧" | 双端点 `[a, b]` |
| 运输问题 | "运输问题"+"最小元素法"+"初始" | ≥2 个分配量 |
| 比较建议 | "比较"+"建议"/"选择"/"哪个更优" | 建议/选择结论 |
| 矩阵展示 | "矩阵方法"+"回归"/"OLS" | 中间矩阵 |
| 枚举所有解 | "列出所有/求出所有/互不同构" | 多个对象 |

**设计哲学**：**宁松勿严**——漏报（没检测到缺失但实际缺失）代价低（维持现状），误报（检测到缺失但实际不缺）代价高（可能错误替换正确答案）。

**回捞机制**：
- `recover_hypothesis_conclusion(fulltext)`：从完整解题文本中回捞假设检验结论（要求有"因此/所以/故"等引导词）
- `recover_confidence_interval(fulltext)`：从完整解题文本中回捞最后一个 `[9.03, 11.97]` 格式的区间

### 4.3 交叉验证架构（LLM vs Python）

**核心流程**：
```
                    ┌─────────────┐
    题目 ──────────→│  LLM 推理链  │────→ LLM答案
                    └─────────────┘         │
                                            ├──→ AnswerMatcher
                    ┌─────────────┐         │     │
                    │ Python执行   │────→ Python答案──┘
                    └─────────────┘
                                              │
                          ┌───────────────────┤
                          ▼                   ▼
                      match              mismatch/uncertain
                          │                   │
                    直接通过           reconciliation重试
                                          或强制选优选
```

**符号等价性判定**（`_sympy_equivalent`）：

1. **预处理**：Unicode 归一化（−→-、×→*、²→**2、½→(1/2)）、√→sqrt、LaTeX 转换
2. **SymPy 等价**：`simplify(e1 - e2) == 0`
3. **数值回退**：如果含自由符号，用 30 位精度数值比较
4. **矩阵结构比较**：形状不同→不等价；`simplify(e1-e2).is_zero_matrix`
5. **不确定**：含自由符号无法数值比较→返回 None

**答案优选**：
- Python 成功 → Python 答案优先（确定性 > LLM 文本）
- Python 失败 → LLM 推理答案
- 缺契约字段时回退到更完整的答案

| 优先级 | 机制 | 理由 | 实现难度 |

| **P0** | 截断代码恢复 | 零依赖，直接复用 `_recover_truncated_code` | 极低 |
