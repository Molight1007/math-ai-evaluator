1题型识别与快车道分流
题型识别 ClassifierAgent
读取元数据：domain 已知（如"代数/几何/数论"）→ 直接跳过 LLM；未知 → 一次性分类识别题型与领域，注入后续求解提示词。
快车道 SymPy 确定性求解
✓ 算术 / 求导 / 积分 / 行列式 / 方程 / 极限 → 计算器直出结果，零 LLM 开销，直接进入验证。
求解通道 SolverAgent
→ 复杂/证明类题目进入多候选并行求解（见阶段 2）。
2并行求解（多策略 × 多候选）
初始求解 SolverAgent._generate_initial
并行生成 3 个候选解，各候选使用：蓝图分解（先规划证明框架再填充）+ 领域提示（30+ 领域针对性模板）+ LemmaRepo 引理注入（复用已沉淀结论）。
蓝图分解领域提示词 ×30+LemmaRepo 引理注入3 候选并行
证明题专用 _generate_proof
prefill 抑制 CoT 输出，直接生成严格证明文本；可选接入 LeanBridge 形式化验证（侧链）。
截断续写 complete_truncated
输出被截断（token 上限）的候选自动续写补齐，避免浪费。
子目标补充 SubGoalSolverAgent
候选不足或证明题时启用：plan → step → merge 子目标分解；新增轻量 AND-OR 蓝图（直接失败→分解子目标→LLM Reviewer 过滤无前景分支→递归求解→回溯），深度受预算限制。

3验证与聚簇
多票验证 VerifierAgent._vote_one
每个候选独立 A/B 双路投票（prefill "VERDICT: " 抑制 CoT 防偏），综合置信度；投票数随时间档位收紧（3→2→1）。
A/B 双路prefill 抑制 CoT置信度综合
等价聚类 _cluster_candidates
文本归一化 + SymPy 符号等价判断 → AnswerCluster 答案簇，多候选命中同一答案即聚簇提权。
证明逐步骤验证 _verify_proof_step
证明题按步骤审查，产出 BugReport（Critical / Gap + severity + repairable 可修复性 + suggestion 修正建议）。
4验证-精炼闭环（AcceptGate）
🔄 精炼闭环  |  IMO2025 验证-精炼流水线思想
门控条件（RoundState 计数）：
▸ ACCEPT：验证连续通过 ≥ 5 次 或 置信度 ≥ 接受阈值 → 进入格式化
▸ REJECT：连续重大缺陷 ≥ 10 次 → 放弃该候选
▸ HOLD：提取 revise_feedback（优先结构化 BugReport 建议）→ 回 SolverAgent._generate_revise 纠错重解 → 重新验证
修订重解 SolverAgent._generate_revise
携带上一轮反馈重新求解（修正推导/补充 gap/重写证明），进入下一轮验证。预算耗尽或全部 REJECT 时退出循环。
revise_feedback 驱动≤ 预算约束
5引理沉淀 · 兜底 · 输出
引理沉淀 SummarizerAgent
从成功解答提取可复用中间结论 → 写入 LemmaRepo（线程安全），后续题目求解时注入复用。✓ 跨题知识积累
兜底直答 direct_solve
全部候选 0 正确票 时，用内置后端直接作答，保证"每题必有输出"。
共识格式化 FormatterAgent
取最高票答案簇 → 标准化输出格式（答案 + 解析过程）→ 返回 final_response + trace + candidates + verdicts + clusters 完整审计链路。
SLean 形式化验证侧链（LEAP 思想）
LeanBridge agent/lean_bridge.py
将 NL 推理翻译为 Lean 4 形式化证明并交给编译器验证，四阶段流水线：
convert（NL→Lean）→ compile（lean 编译器，60s 超时）→ analyze（错误归类）→ fix（可自动修复）；结果映射为 BugReport 反馈驱动精炼闭环。
convert→compile→analyze→fix开关 enable_lean_verify（默认关）Lean 缺失→降级 unknown计入 Budget
