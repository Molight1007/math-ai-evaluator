## 用户需求

对项目全部代码文件进行规范化处理，删除无用注释，添加中文注释解释代码逻辑，修复已知 bug。

## 核心功能

1. **删除无用注释**：移除 launcher.py 中重复的注释、各模块中与代码自解释重复的冗余注释、无实际价值的过度分隔注释
2. **添加中文注释**：为每个 .py 文件的模块、类、关键函数添加中文 docstring；为复杂算法逻辑添加行内中文注释；为 .bat 和 .js 文件添加中文注释说明
3. **删除废弃文件**：删除 `测试工具/main_test.txt`
4. **修复 5 个 Bug**：

- 修复 `测试工具快捷启动/启动评测器.bat` 工作目录错误
- 删除 `launcher.py` 第 810 行重复的 config import
- 将 `question_bank.py` 第 468 行 `import uuid` 移至文件顶部
- 将 `convert.py` 和 `docx_to_json.py` 中函数内的 `import json` 移至文件顶部
- 将 `make_ppt.js` 硬编码绝对路径改为相对路径

## 技术方案

### 实现策略

采用**逐文件处理**方式，按模块分组依次处理每个代码文件。每个文件执行三类操作：注释清理、中文注释补充、Bug 修复。

### 处理原则

- **保留所有有用注释**：模块级 docstring、函数 docstring、关键逻辑说明、结构分区注释（保留一份即可）
- **删除无用注释**：完全重复的注释、与代码自解释内容重复的注释、无实际说明价值的装饰性分隔符
- **添加中文注释**：为每个公开函数/类添加中文 docstring（保留原有英文 docstring 作为补充）；为复杂逻辑（JSON 提取回退、字符映射、异步线程嵌套）添加行内中文注释
- **最小改动原则**：仅修改注释和修复 bug，不重构代码结构、不改变函数签名、不修改业务逻辑

### 文件处理分组

按模块相关性分为 6 组，每组内文件共享相似的处理模式：

| 分组 | 文件 | 处理重点 |
| --- | --- | --- |

| 业务模块 | loader.py, intern_s1.py, deepseek.py, aggregator.py | 补充中文 docstring + compute_summary 返回结构注释 |
| 入口模块 | main.py, reporter.py, launcher.py | 注释清理 + 补充中文注释 + 修复重复 import bug |

| 脚本文件 | 启动评测器.bat, 快捷启动/启动评测器.bat, make_ppt.js | 添加中文注释 + 修复 bat 路径 bug + 修复 js 硬编码路径 |
