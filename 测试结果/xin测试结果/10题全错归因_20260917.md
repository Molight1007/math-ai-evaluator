### 2.2 为什么它是致命的

**验证器 18 票说"6 个候选全错"→ 系统丢弃全部候选，改用一次没有任何验证覆盖的临时直答，且以 `confidence=0.0` 采纳。**

这是逻辑倒置：**验证越确信候选是错的，系统越信任一个更没依据的答案。**

10 题里有 **5 题**（003/013/002/032/025）触发此路径，全部 `pick_diag = {}`（事后完全无法追溯）。

## 三、第二发现：`</tool_call>` 工具残留仍污染候选（BUG-1 未修全）

### 3.1 铁证：025 的 6 个候选

| 候选 | answer 字段 | reasoning 字段 |
|---|---|---|
| 0 | `</tool_call>` | 1000+ 字符完整推理 |
| 1 | `</tool_call>` | 1000+ 字符完整推理 |
| 2 | `</tool_call>` | 1000+ 字符完整推理 |
| 3 | `</tool_call>` | 1000+ 字符完整推理 |
| 4 | `509040-2*169680`（未求值） | — |
| 5 | `</tool_call>` | 1000+ 字符完整推理 |

**5/6 = 83% 污染率**。而最终答案取自候选 4 的未求值表达式 `509040-2*169680`（=169680），gold = 506。

### 3.2 根因：三条「原文尾部切片」路径根本不过剥壳函数

`utils/extract.py` 已修的三条路径（`extract_final_answer` / `rescue_final_answer` / `smart_fallback_answer`）**没有覆盖**下列位置 —— 它们直接把 LLM 原文切片当答案：

| 文件:行号 | 函数 | 代码 | 风险 |
|---|---|---|---|
| `agent/sub_goal_solver.py:1962` | `_call_step` | `return resp.strip()[-500:]` | **极高** |
| `agent/sub_goal_solver.py:1958-1960` | `_call_step` | 正则 `【本步结果】(.*?)(?:$ 或 【)` 直接切片 | **高** |
| `agent/sub_goal_solver.py:3158-3164` | `_fallback_from_last_subgoal` | `return sg["result"]`（原样升格） | **极高** |
| `agent/solver.py:1431-1432` | `_generate_proof` | `answer = raw[-500:]` | **极高** |

**关键：全项目不存在通用收敛点。** `Candidate` 是普通 `@dataclass`（`agent/base.py:190-201`），**无 `__post_init__`**，无 `_normalize_candidate` / `_sanitize_answer`。任何绕过抽取函数的路径都能把脏字符串直接落进 `candidate.answer`。

### 3.3 为什么 025 的 reasoning 是完整的、answer 是 `</tool_call>`

模型用 XML 风格写工具调用（`<tool_calls><function=...><parameter=...>`），该格式不被 `base.py::llm_with_calc` 识别（它只解析标准 `resp["tool_calls"]`），**响应原样返回**。prefill 种子 `【本步结果】` 让模型把工具 XML 紧跟种子输出 ⇒ 切片捕获到 `<parameter=...></parameter></function></tool_calls>`，`.strip()` 后**末尾正是 `</tool_call>`**。`_strip_check_tags`（`:740`）只认 `<check>`，对 `</tool_call>` 无效。

## 六、第五发现：DAG 蓝图与子目标环节的缺陷

### 6.1 子目标截断**丢弃中间节点但不清理依赖边**

`agent/blueprint_planner.py:56-87`：
> MAX_SUBGOALS = 6
> def cap_subgoals_keep_last(items: list, max_n) -> tuple:
>     if max_n <= 0 or n <= max_n: return seq, []
>     if max_n == 1: return seq[-1:], seq[:-1]
>     return seq[:max_n - 1] + seq[-1:], seq[max_n - 1:-1]   # ← 前7个 + 最后1个，中间全丢
`max_n=8` 时是「前 7 个 + 最后 1 个」。**中间被丢弃的子目标若被存活节点依赖，依赖会被静默过滤**（`to_subgoal_plan` 中 `depends_on` 按 `d in order` 过滤，`:204`）⇒ 下游子目标**丢失前置结论却无任何告警**。

⚠ **注**：用户 2026-09-15 删的是**阶段时间帽**（`phase_budget_enabled=False`），**数量上限没删**（反而从 6 放宽到 `{standard:8, deep:16}`，`user_agent.py:647`）。

### 6.2 "时间不够就跳过子目标"逻辑**仍有 4 处残留**

`agent/sub_goal_solver.py`：
- `:585-595` —— `if ctx.gen_time_up(): break`（跳过剩余子目标）
- `:617` —— 重试带 `_stage_left() > 120` 闸
- `:639` —— 轻校验带 `_stage_left() > 90` 闸
- `:693` —— 自适应恢复带 `_stage_left() > 150` 闸

### 6.3 `_fallback_from_last_subgoal` 用中间结果冒充最终答案

`agent/sub_goal_solver.py:3158-3164`：
> @staticmethod
> def _fallback_from_last_subgoal(subgoals: list[dict]) -> str:
>     for sg in reversed(subgoals):
>         if sg.get("result"):
>             return sg["result"]      # ← 只取最后一个子目标，前面全部丢弃
>     return "无法求解"
**4 处调用**：`:795`（全局预算不足）、`:2914`（merge 返回 None）、`:2962`（merge 二次失败）、`:2971`（未提取到最终答案）。

这与实测错误形态**完全吻合**：015「`n ≥ 2` 而 gold=2」、064「`m is even` 而 gold=4」、**099「只答一半」**、108「`增大` 而不完整」。

### 6.4 子目标链"单入口 + 无独立分支"

`diag.subgoal_stats`：`{"n_subgoals": 7, "dep_edges": 21, "avg_indegree": 3.0, "dep_free": 1}`
**`dep_free = 1`** —— 整条链**只有一个无依赖入口**。首个子目标一旦断言错，全链建立其上，`_format_dep_results`（`:3051-3090`）只注入直接依赖，**没有任何并行独立分支做交叉验证**。

### 6.5 DAG 重规划结果**被丢弃**

`agent/sub_goal_solver.py:854-978`（`_review_and_maybe_replan`）全程操作**局部变量 `dag`**（`:931, :951` `dag = new_dag`），**无一处 `ctx.blueprint = ...` 回写**。
⇒ 实测 9 题 `dag_review = {}`、`dag_replan_events = []` —— **重规划即使跑过也白跑，下游继续用旧蓝图**。这与"revise 把 d=50 改坏成 19"是同一失效面。

### 6.6 蓝图 OR 节点只取第一个分支

`agent/blueprint_planner.py:254-255`：
> else:  # or：取第一个 child（主策略分支）
>     expand(node.children[0])
**OR 分支的其余备选解结构性丢失** —— 对"多解/多方法"题会永久丢掉正确路径。

## 九、结论与修复优先级

### 9.1 为什么 10 题全错 —— 三层叠加

1. **模型层（根因）**：方向性错误为主（方法不适用 / 前提不成立 / 漏项），且**候选项高度一致地错**（086 的 6 个候选全给 `8`；091 的 6 个候选全给同一错式）⇒ **自洽性投票在此完全失效**（一致地错，投出来还是错）。
2. **机制层（放大器）**：全 0 票 → **零票兜底**用未经验证的直答覆盖 → `pick_diag` 空 → 无法追溯。且 `LeanGate` 对错答案放行（003/086 各 7 次 `answer_valid`）。
3. **数据层（污染源）**：三条 `[-500:]` 切片路径产出 `</tool_call>` / 代码 / 搜索词，占 025 候选的 83%，并通过 `_fallback_from_last_subgoal` 升格为最终答案。

### 9.2 修复优先级（按性价比）

| 优先级 | 修复点 | 位置 | 理由 |

| **P0** | 零票兜底纳入统一校验（失败回落 `_pick_best` 而非置空） | `agent/formatter.py:92` 后 | 切断"验证越确信越信直答"的倒置 |
| **P1** | 补三条切片路径的剥壳 | `sub_goal_solver.py:1958/1962/3163`、`solver.py:1432` | 堵住污染源头 |
