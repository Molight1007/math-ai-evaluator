# LLM 数学认知探针（MathCog Probe）

> 科学问题：**大模型在数学推理中是否具备「联想 / 类比」能力？它能否观察到更本质的数学结构？**
>
> 方法创新：用 **Lean 4 形式化验证** 作客观尺子，并用 **证明结构指纹** 把"方法迁移"
> 从主观判断变成可计算的连续量。

---

## 一、科学问题（及其由来）

智能体工程跑通之后，剩下的错误几乎都来自**模型输出本身**：蓝图骨架错、子目标求解失败、
超时跳过验证。继续打补丁的边际收益在下降，于是问题回到上游：

| 老师的问题 | 本项目的操作化定义 |
|---|---|
| "它有否联想的功能" | 见过结构同构的源题后，能否把方法迁移到表层不同的目标题 |
| "能否观察到更本质的数学结构" | 解完题后能否**命名**所用结构；给定结构名能否**构造**出体现它的最小证明 |
| "不能因短板忽视它可能没呈现的长板" | 除了记录失败，也要设计能**捕捉到**结构洞察的实验（反向构造任务即为此设） |

## 二、方法核心：把"结构"变成可计算的量

过去测"模型有没有理解结构"只能靠人读答案打分——主观、不可规模化、无法复现。

这里换成一个可计算的代理量：

> **一个证明用了哪些 tactic / 引理  ==  它走的是哪条"结构路径"**

例如同样是不等式：

| Lean 证明写法 | 反映的结构路径 |
|---|---|
| `nlinarith [sq_nonneg (a - b)]` | 配方法 / 平方和非负 |
| `nlinarith`（裸用） | 暴力代数消元 |
| `induction` + `ring` | 归纳结构 |

于是"方法有没有迁移过去"被量化成两个集合的重合度（`judge/fingerprint.py`）：

- **核心迁移率** = 目标题指纹 ∩ 共享结构核心 ÷ 共享结构核心
- **方法继承率** = 目标题指纹 ∩ 源题指纹 ÷ 源题指纹

**这是本实验相对"选择题自评"类工作的主要区别点**：判据是编译器，不是模型自己。

## 三、五类探针

| 探针 | 测什么 | 范式 | 客观判据 |
|---|---|---|---|
| **A 同构迁移** | 联想能否发生 | 源题 → 目标题（带/不带源题对照） | Lean 编译 + 指纹重合度 |
| **B 陷阱题** | 类比是否用错地方 | 表层像模板 X、实则需要 Y | 文本标记 + Lean 验证 |
| **C 结构指认** | 元认知 | 正向选择结构名；**反向给结构名造最小 Lean 示例** | 选择题准确率 + 反向编译率 |
| **D 抽象⇄实例化** | 抽象层级 | 具体→一般公式；一般→具体反例 | 正则匹配 + Lean 验证 |
| **E 陈述完整性** | **严格理解的最后一公里** | **自己完整说出定理的全部条件**（主动） | 条件清单逐项匹配 + Lean 特例编译 |

### 为什么 B/D 之外还要有 E：判断层 ≠ 陈述层

| | 判断层（B / D 已覆盖，**被动**） | 陈述层（E，**主动**） |
|---|---|---|
| 拉格朗日中值定理 | 把"开区间可导"去掉，看它能否识破 | 让它自己写出「闭区间连续**且**开区间可导」 |
| 费马小定理 | 把素数 p 换成合数 4，看它能否找反例 | 让它写出「p 是素数 **且** p ∤ a **且** a^(p-1) ≡ 1 mod p」 |
| 柯西-施瓦茨 | 内积空间条件缺失时能否识破 | 让它说出「内积空间 + 正定性」 |

**能判断 ≠ 能精确陈述。** 识破"去掉可导条件"是一回事，自己完整列出条件是另一回事。

### 探针 E 的四道题（三个子维度）

| 题 | 定理 | 子维度 | Lean 判据 |
|---|---|---|---|
| E1 | 拉格朗日中值定理 | 条件完整性 | ✅ 用 `Set.Ioo` 把"中值点必须在开区间内"编进命题（绕开 `deriv`） |
| E2 | 费马小定理 | 量词 + 模运算 | ✅ (p=11, a=2) 特例，`norm_num` 可验 |
| E3 | 柯西-施瓦茨不等式 | 适用范畴 | ✅ n=2 实数版，`nlinarith [sq_nonneg (a1*b2 - a2*b1)]` 一步证毕 |
| E4 | 一致收敛换极限 | 隐含条件 | ❌ 涉及极限，**`gold_lean=""` 降级为纯文本判据** |

E 组采用**混合判据**：① 文本条件完整率（关键条件清单逐项正则匹配）+
② Lean 特例编译率。无判据的题只按 ① 计，不拉低 ② 的通过率。

> 详见 [`探针E_陈述层_设计方案.md`](探针E_陈述层_设计方案.md)。

### 探针 A 的三对同构题（迁移难度梯度）

| 题对 | 类型 | 共享结构核心 |
|---|---|---|
| A1 | 近迁移：二元→三元 | 移项配成若干个完全平方之和 |
| A2 | 近迁移：平方差→立方和 | 多项式展开恒等变形（`ring`） |
| A3 | **跨域迁移**：双变量不等式 → 单变量二次型配方 | 配方 `(x-1)²` + 平方非负 |

A3 是关键：表层从"不等式"变成"函数恒非负"，模型要认出二者是同一结构，才谈得上联想。

### 探针 B 的三道陷阱题（测"类比用错地方"）

| 题 | 表层诱导 | 正解 |
|---|---|---|
| B1 | 套**两项** AM-GM 求 `x²+2/x` 最小值 | 需拆三项，最小值 3（x=1） |
| B2 | 前 40 项全是素数 → 模式外推"恒成立" | n=40 时 1681 = 41² |
| B3 | 类比欧几里得引理「p 素数，p\|a² ⟹ p\|a」 | 4 不是素数，反例 n=2 |

**B3 是最锋利的一题**：它测的正是"类比是否恰当"——老师关心的核心。

### 探针 C 的反向任务（硬判据）

给结构名 → 要求写出体现该结构的**最小可编译 Lean 代码**。
能命名 ≠ 能构造：要写出 `induction` 才算真懂归纳，写不出就是背名词。
这是本实验特意设计的"防伪"环节。

### 探针 D 的最强判据

D3（勾股数参数化）：模型给出的 `a,b,c` 参数化若正确，Lean 用 `ring` 一步验证
`(m²-n²)² + (2mn)² = (m²+n²)²`；给错则立刻编译失败。**不需要人去读它的推导。**

## 四、指标体系

| 指标 | 定义 | 怎么读 |
|---|---|---|
| `transfer_gain` | 带源题正确率 − 基线正确率 | \>0 说明"做过一遍确实有用" |
| `mean_core_cov_delta` | 带源题 vs 基线的**核心迁移率**之差 | 本实验最原创的量，直接反映结构迁移 |
| `escaped_rate` / `trapped_rate` | 陷阱题识破率 / 被套路率 | 高 trapped = 类比经常用错地方 |
| `articulate_accuracy` | 结构指认选择题准确率 | 需与随机基线（1/12）比较 |
| `reverse_family_hit_rate` | 反向任务是否用上该结构的 tactic/引理 | 与上一行对比，可识别"背名词" |
| `reverse_lean_ok_rate` | 反向任务构造的 Lean 能否编译 | 真懂的下限 |
| `condition_completeness_rate` | E 组：关键条件被说出的平均比例 | < 0.7 = "会用但说不清" |
| `full_statement_rate` | E 组：**一条条件都没漏**的比例 | **E 组主指标**，最严格 |
| `lean_special_ok_rate` | E 组：定理特例的 Lean 编译通过率 | 与上一行比对：**都高 = 真懂**；只高 Lean = 套模板 |
| `both_pass_rate` | E 组：条件说全 **且** 特例编译过 | E 组 headline 指标 |

## 五、项目结构

```
论文实践/
├── config.py              全局配置（模型、Lean 路径、并发参数）
├── run.py                 主入口（--check / --mode gold|dry|live）
├── util.py                从模型输出抽代码、抽答案
├── record.py              统一的实验记录结构
├── llm/client.py          OpenAI 兼容客户端 + 推理模型支持 + 缓存 + dry-run
├── bank/problems.py       ★ 五类题库（含结构标注、gold Lean 代码、E 组关键条件清单）
├── judge/lean.py          ★ Lean 4 客观判据（编译 / sorry 检测）
├── judge/fingerprint.py   ★ 证明结构指纹（方法迁移的可计算代理）
├── probes/                A 迁移 / B 陷阱 / C 结构 / D 抽象 / E 陈述完整性
├── analysis/              指标汇总 + 报告生成
└── results/               每次运行的产出（含 lean_debug 失败样本）
```

## 六、运行

```bash
# 1. 环境自检（不花钱）
python run.py --check

# 2. 离线自检判据：把题库自带的正解全编译一遍（不联网，验证"题出得对不对"）
python run.py --mode gold

# 3. 假模型跑通管线（不联网）
python run.py --mode dry --probe A
python run.py --mode dry --probe E --no-lean     # 单独验 E 组管线

# 3.5 文本判据自检（不联网、不花钱、3 秒）—— 加题后必跑，见 §七
python run.py --mode criterion

# 4. 真跑（建议先用 E 组 4 题试水，8 min 暴露输出格式与判据问题）
python run.py --probe E --model deepseek
python run.py --probe A B --model deepseek
python run.py --probe all --model deepseek --repeat 3   # 多轮采样统计随机性
python run.py --probe A --no-lean                        # 只收自然语言结果
```

> ⚠️ `--mode gold` 会逐个编译全部 32 道题，约 8 min，**超过常见的 2 min 前台超时**，
> 请用后台方式跑，否则会被 SIGTERM 打断。

产出在 `results/<时间戳>_<模型>/`：

| 文件 | 用途 |
|---|---|
| `report.md` | 人读的汇总报告 |
| `per_item.csv` | 明细表（Excel 可直接打开，utf-8-sig） |
| `raw.jsonl` | **全量原文**，含模型完整输出，供人工复核 |
| `summary.json` | 机器可读的指标 |

## 七、当前环境与已知限制（诚实声明）

| 项 | 状态 |
|---|---|
| Lean 4.31.0 + Mathlib 闭包（338 olean，只读引用主项目） | 可用（预热 ~15–35s，单题编译 ~13s） |
| `Intern-S2-Preview-397B` | 可用 |
| `deepseek-v4-flash` | 可用，**是推理模型**（思维链在 `reasoning_content`，max_tokens 必须给足） |
| 题库规模 | A 8 对 / B 6 题 / C 10+4 / D 5 / **E 4** = **53 条记录/轮**；仍偏小，须多轮采样后方可谈统计 |

⚠️ **踩过的坑（务必知道）**：本机 shell 里残留了一个**已过期**的 `INTERN_API_KEY`
（同为 51 位，极易混淆）。若按常规 dotenv 约定"已存在的环境变量不覆盖"，
`.env` 里正确的 key 会被这个陈旧值遮住，表现为 `user token expired`。
因此 `config.load_main_env()` 默认 **以 .env 覆盖同名环境变量**。
需要保留外部注入时设 `MATHPILOT_ENV_NO_OVERRIDE=1`；用 `python run.py --check`
可看到脱敏后的实际生效 key，便于确认没被遮住。

⚠️ **最危险的一类坑：判据静默失效**（2026-09-05 实测抓到的）：

正则判据写错时**不会报错、不会崩溃**——它只是安静地把所有模型判成"漏条件"，
然后你拿着一份看起来很合理、实则完全错误的报告去写论文。这是本项目
**唯一一类不会自己暴露的错误**。

当天抓到的两个实例：

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | E3 的"完美回答"被判为漏条件 | 正则只写 Unicode 范数 `‖u‖`，模型用 ASCII `\|\|u\|\|` | 加 `util.normalize_math()` 统一记号 |
| 2 | 英文正确回答被判为漏条件 | 正则以中文为主，`inner product space` / `linearly dependent` 匹配不上 | 所有条件正则**一律写中英双语变体** |

`normalize_math()` 会把 `‖`/`\|\|`/`\|` → `\|`，`⟨⟩` → `<>`，`·`/`×` → `*`，
`≤` → `<=`，并处理 `\leq` / `\langle` 等 LaTeX 写法（**刻意保留** `∤` 与 `≡`，
E2 的正则依赖它们原样出现）。

因此新增任何基于正则的文本判据后，**必须跑**：

```bash
python run.py --mode criterion
```

它用三条语料卡住判据（`judge/criterion.py`）：

| 语料 | 期望 | 抓什么错 |
|---|---|---|
| `perfect` | **全命中** | 正则太窄 → 漏判 |
| `vague` | **漏命中** | 正则太松 → 分不出"真懂"与"会说" |
| `variants` | **全命中** | 记号 / 语言变体没覆盖 |

语料在 `bank/problems.py` 的 `E_SELFTEST`，**加题时必须同步补**。

⚠️ **写 gold Lean 代码的三个坑**（都已踩过，别再犯）：
1. 闭包**不含 BigOperators 的 `∑` 记号** → 求和类命题改用"递归定义 = 闭式"的归纳形式。
2. 绝对值三角不等式的引理名是 **`abs_add_le`**，不是 `abs_add`（后者是 unknown identifier）。
3. `field_simp [hx]` 常常**已经把目标解完了**，再单独写一行 `ring` 会报
   `No goals to be solved` → 写成 `field_simp [hx] <;> ring` 两种情况都安全。

新增题目后务必跑 `python run.py --mode gold`：它会逐题打印编译结果与抽取到的指纹，
是唯一能廉价发现"题出错了"的手段（不联网、不花钱）。

**必须承认的边界**：

1. **样本量小**：单轮结果只能作定性信号。正式结论需 `--repeat N` 多轮采样报告均值与方差。
2. **判据边界**：Lean 判"形式化证明是否成立"，不判"数学洞见是否优雅"。
   模型可能写出编译通过但结构笨拙的证明，需结合指纹人工复核。
3. **文本标记的局限**：B 组的 trapped/escaped 依赖关键词匹配，会有 `mixed` / `other`
   两类，报告中单列，**不做强行归类**。
4. **单模型不成结论**：框架已多模型可插拔，跨模型对比才谈得上"LLM 是否有联想能力"。

## 八、论文路线图（建议）

1. **扩题库**：每类探针扩到 20–30 题，覆盖代数 / 数论 / 组合 / 几何四个领域。
2. **多模型对比**：Intern-S2（换新 key）、DeepSeek、GPT 系、开源小模型，看"联想能力"
   是否随规模涌现。
3. **人机对照**：找数学专业学生做同一批题，给出人类基线——这是论文最有说服力的对照。
4. **失败模式分类学**：把 `results/lean_debug/` 里的失败样本归类，
   回答"模型到底在哪个环节丢失了结构"。
5. **核心论点**：若实验显示「能解对题但核心迁移率低」，则结论是
   **大模型擅长模式匹配、弱于结构迁移**——这正是对"联想能力"的定量回答。
