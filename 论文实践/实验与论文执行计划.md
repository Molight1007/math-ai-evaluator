## 🎯 本次实验的核心目的（用户 9/5 明确表述）

> **① 测试 LLM 有没有「联想」的功能；**
> **② 测试 LLM 能不能「正确理解数学严格的公式定理」。**

这两句就是整篇论文的**中心论点**。所有探针设计、题目选取、指标定义，
都必须能向上追溯到其中之一——追溯不到的，就是可以砍掉的题。

**第二句的「严格」二字是重点**：不是"大概会用公式"，而是
**精确知道定理的条件与边界**（条件必不必要、定义域能不能扩、量词与取等条件对不对）。

### 两个目的 → 探针 → 指标 的追溯表

| 核心目的 | 具体问法 | 对应探针 | 观测指标 |
|---|---|---|---|
| **① 有没有联想功能** | 做过结构同构的源题后，能否把方法搬到**表层不同**的目标题 | **A 同构迁移** | 迁移增益、**核心迁移率**、方法继承率 |
| | 给一个结构名，能否造出体现它的最小证明（能命名 ≠ 能构造） | **C 反向构造** | 结构命中率、反向编译率 |
| | 能否从若干具体实例抽象出一般公式 | **D c2g** | 抽象命中率 |
| **② 能否正确理解严格的公式定理** | 定理的**条件**被改动时，能否识别失效并构造反例 | **B 陷阱 / D g2c** | 识破率、抽象命中率 |
| | 公式的**定义域**被扩大时，能否察觉结论不再成立 | **B5**（定义域迁移） | 识破率 |

## 二、今日修掉的一个真 bug（重要，避免复现）

`config.load_main_env()` 原本按常规 dotenv 约定"已存在的环境变量不覆盖"，结果
**本机 shell 里残留的过期 `INTERN_API_KEY`（同为 51 位）把 `.env` 里正确的 key 遮住了**，
表现为 `user token expired`，一度误判为"密钥过期"。

- 修复：改为**默认以 `.env` 覆盖同名环境变量**（本项目 `.env` 为权威配置源）。
- 诊断：`python run.py --check` 会脱敏打印实际生效的 key，一眼看出是否被遮住。
- 复核证据：用 `.env` 中的 key 直连 API 返回 `"2"`，正常。

## 二之二、今日抓到的**判据静默失效** bug（比上一个更危险）

`--mode criterion` 自检时暴露：E3 的**完美回答**被判为"漏条件"。

| # | 症状 | 根因 | 危害 |
|---|---|---|---|
| 1 | 完美回答命中 2/3 | 正则只写 Unicode 范数 `‖u‖`，模型用 ASCII `\|\|u\|\|` / `\|u\|` | **所有模型被系统性误判为漏条件** |
| 2 | 英文正确回答命中 1/3 | 正则以中文为主，`inner product space` / `linearly dependent` / `exchange limit` 匹配不上 | 模型换语言作答即失效 |

**为什么这比崩溃危险得多**：判据正则写错时**不报错、不崩溃**，只是安静地
把所有模型判成"漏条件"，然后你拿着一份看起来很合理、实则完全错误的报告去写论文。
这是本项目**唯一一类不会自己暴露的错误**。

**修复**：

1. 新增 `util.normalize_math()`：把 `‖` / `\|\|` / `\|` → `\|`，`⟨⟩` → `<>`，
   `·` `×` → `*`，`≤` → `<=`，并处理 `\leq` `\langle` `\|` 等 LaTeX 写法
   （**刻意保留** `∤` 与 `≡`，E2 的正则依赖它们原样出现）。
2. 所有条件正则**一律写中英双语变体**。
3. 新增 `python run.py --mode criterion`（不联网、3 秒），用 `perfect` / `vague` /
   `variants` 三条语料卡住判据两端与鲁棒性。
4. `hits_any()`（B/D 组的陷阱标记匹配）同步加归一化，防同类问题。

**当前状态：17/17 全过。**

> **纪律**：以后**每加一道依赖文本正则判据的题，都必须同步补 `E_SELFTEST` 语料并跑
> `--mode criterion`**。这是跑实验前唯一能廉价发现判据失效的手段。

## 三、科学问题 → 操作化定义（论文的骨架）

| 老师的问题 | 本项目的操作化定义 | 对应探针 |
|---|---|---|
| "它有否联想的功能" | 见过结构同构的源题后，能否把方法迁移到**表层不同**的目标题 | **A 同构迁移** |
| "能否观察到更本质的数学结构" | 解完题后能否**命名**结构；给定结构名能否**构造**出体现它的最小证明 | **C 结构指认**（正向 + 反向） |
| "不能因短板忽视它可能没呈现的长板" | 设计能**捕捉到**结构洞察的实验，而非只记录失败 | C 的反向任务、D 的参数化抽象 |
| （延伸）类比会不会用错地方 | 表层像模板 X、实则需要 Y 时是否会被骗 | **B 陷阱题** |
| （延伸）抽象能力 | 具体⇄一般的双向映射 | **D 抽象⇄实例化** |

### 方法创新点（论文卖点）

> **证明结构指纹**：一个证明用了哪些 tactic / 引理 == 它走的是哪条"结构路径"。

过去测"模型是否理解结构"只能靠人读答案打分——主观、不可规模化、不可复现。
本项目把它变成两个集合的重合度：

- **核心迁移率** = 目标题指纹 ∩ 共享结构核心 ÷ 共享结构核心
- **方法继承率** = 目标题指纹 ∩ 源题指纹 ÷ 源题指纹

并且**判据是 Lean 编译器，不是 LLM 自评**——这是相对"选择题自评"类工作的根本区别。
