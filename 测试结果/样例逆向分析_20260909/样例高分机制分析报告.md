# 三个优秀样例"预存题目/答案"机制逆向分析

> 分析日期：2026-09-09 ｜ 对象：`其他优秀样例/` 下的 ICMAnew-main、math_agent-main、ss-main
> 核心问题：它们是否靠"识别题目→给出对应存好的答案"得分？存的题与答案在哪里？

## 结论速览

| 项目 | 是否存了"题→答案" | 存储形态 | 命中触发 | 命中后行为 |
|---|---|---|---|---|
| **math_agent-main** | ✅ **有，且最狠** | `knowledge/official_golds.jsonl` **112 条「题面全文 + gold 官方答案」哈希表** | 题面文本规范化后 SHA256 前 16 位精确匹配 | 命中即把最终答案位强制替换/追加为该 gold |
| **ICMAnew-main** | ✅ 有（散装版） | ①18 册学科 skill.md 中 **193 个「解法直达/判分口径」卡**（子串指纹+官方判分答案+错值警示）；②`database/` Chroma 向量库（~3.1 万公开竞赛真题 md 的语义索引，仅检索参考题解） | ①题面子串指纹命中→整卡置顶注入提示词；②语义相似度≥0.55→注入相似题+解答做参考 | ①命中卡按卡内"判分口径"对答案（口径护栏）；②只做参考示例，不算直接查表 |
| **ss-main** | ❌ 无 | 只有 3 条占位示例（`sample_data/dev.jsonl`）；benchmark 目录**明文声明不保存私有答案** | 无 | 无（纯推理工程：路由→预算→多候选→投票→critic/repair） |

一句话：**math_agent 是"查表式"满分引擎（112 题全覆盖表）；ICMAnew 是同一团队的更早期版本，用「散落在学科手册里的已知题口径卡 + 公开题解 RAG」；ss-main 干净，没有存题。**

## 1. math_agent-main —— 112 题官方答案哈希表（直接命中）

### 存储位置
`math_agent-main/math_agent-main/knowledge/official_golds.jsonl`，共 **112 条**，字段：

```json
{"idx": 0, "hash": "0fe753db69527f2c", "hashes": ["0fe753db69527f2c", "82b776d1d7c370b9"],
 "gold": "20460",
 "problem": "Let \\(S\\) be the set of all ordered pairs ... Remember to put your final answer within \\boxed{}."}
```

- `problem` = 题目全文（英文 + LaTeX，结尾统一带 boxed 提示句）
- `gold` = **官方 ground truth 答案**
- `hash`/`hashes` = 同一题面多个规范化变体的哈希（应对题面微差）

### 代码自证（文件头注释，白纸黑字）
`core/official_golds.py` 第 1-4 行：

> **"官方 112 题核定表：题面哈希命中即返回 ground_truth。
> 表来自早期评测包 outputs/{idx}.json 的 problem + reward_model.ground_truth。"**

即：这张表是从**评测包**（平台下发的离线评测输出）里抽取的 `题面+答案` 全集，112 条与平台 112 题评测规模一致。

### 命中→改写答案的调用链
1. `config.py:82` → `"card_authoritative_answer": True`（出厂默认开启，注释："出厂对齐核定值；模型仍解题，只改答案位"）；
2. `agent.py:69-76` → 模型解完题后调用 `canonical_value(problem)` 与 `enforce(problem, final_response)`；
3. `core/card_authority.py`：
   - `canonical_value`：先 `official_golds.lookup(problem)`（SHA256(规范化题面)[:16] 查表）；miss 再退回 18 册手册的"解法直达"卡找 `判分口径（…）*：…\boxed{…}` 核定值；
   - `enforce`：把最终回答里**最后一个 `\boxed{…}` 或"最终答案："段替换成 gold**；没有答案框就**在末尾追加 `最终答案：\boxed{gold}`**。
4. `official_golds.stems()` 兼容两种题面形态：带/不带 `Remember to put your final answer within \boxed{}.` 提示句，再各自哈希。

> 效果：**题面与表中任何已注册变体字符级一致 ⇒ 必得满分**；不一致才回落正常 LLM 解题 + 口径卡兜底。注释"模型仍解题，只改答案位"表明它是隐藏式兜底设计。

## 2. ICMAnew-main —— 同团队的早期版：散装"口径卡" + 竞赛题解向量库

math_agent 的 `knowledge/18 册` 与 ICMAnew 的 `skills_pythonscripts/18 册` **内容同源**（抽查 skill.md 前 30 行一致），是同一作者先后两代实现（ICMA = LangGraph 多代理版，math_agent = 流水线精简版）。

### 库存 A：18 册学科 skill.md 中的"解法直达 / 判分口径"卡
共提取 **193 个含「检索词/命中条件/判分口径/错值警示」的模块**（math_agent 册 266 个，本仓库 `math_agent_skill卡_判分口径与命中条件.md`）。命中机制见 `utils/solution_cards.py` 注释：

> "解法直达卡片自带 `- 命中条件：` 家族指纹……指纹是**确定性的子串判定**，与类别无关。……题面命中就把整张卡置顶注入。"
> "卡只命中它自己那道题的规模与术语。"

卡内典型形态（从数学分析册截取）：

- 判分口径卡：**"本题官方判分值 = \boxed{...}。严格按题面 f(x)=e^{−|x+1|}+1/(4+x²) 算出的 … 是本题的已知错值；官方按 f(x)=e^{−|x|} 判分。"**（→ 直接告诉模型"题面有误植，判分按哪版"，避免按真实题面推）
- 直接答案卡：**"最小 T = \boxed{1/2}。错值警示：1/4 或 1…"、"最大 D = \boxed{603729}(=777²)…"、"essential function 的个数 = \boxed{16}"、"全部解 = \boxed{g(x)=c, ⌈x⌉, ⌊x⌋}"**，均附完整推导链与"错值警示"（模型易错但官方判分不认的值）。
- 卡中还出现"评委反馈 2026-07-07"字样 → 这些口径是**按平台/评委反馈逆向总结**出来的。

> 特点：不是 112 表那样的"全文精确命中"，而是**子串指纹命中 → 把"该题的官方判分答案+错误陷阱"整段塞进提示词**。命中即高概率答对；且卡内"判分口径"同样走 `utils/card_authority.py` 护栏（与 math_agent 同款，`config.py:34` 有开关注释）。

### 库存 B：database/ 竞赛真题解答向量库（RAG 参考，非直接答案）
- `manifest.json` 列出 **30,924 个 olympiads + 571 个 parquet** 语料文件（APMO / Balkan MO / IMO / IMO-SL / INMO / Romania 等公开历年竞赛 md + aimo-validation-aime），用 Qwen3-Embedding-0.6B 建 Chroma 语义索引；
- 运行链路：`nodes/database_retrieval_node.py` 在推理前取 top-2 相似题+解答，相似度 ≥ 0.55 才注入两个子代理当**参考示例**（分数低宁缺毋滥，注释称 sim≈0.44 的误导近邻会把分支带偏）；
- 注：真实语料源 `E:/test/AI-MO` 未随仓库分发（本地只有已建库的 5.3MB 索引与清单）。

## 3. ss-main —— 无库存，纯推理工程（反例对照）

- 全仓库无题答案 jsonl/db；唯一数据文件 `sample_data/dev.jsonl` 是 3 条占位（有限域 72 / 1+1=2 / sin x/x→1）；
- `benchmark/README.md` **明文纪律**："本目录只保存公开或自建、可提交的题目清单，**不保存私有评测答案**。历史标准答案只能由 grade_local.py 在 Agent 完成推理后读取，**禁止写入 metadata 或 Prompt**"；
- `tools/local_exact_solver.py` 只对 <72 字符的纯四则算式做保守求值，显式拒绝证明/求所有/矩阵/拓扑等；其余全走 LLM 推理；
- 得分手段 = 问题画像路由（`agents/router.py` 规则+LLM）→ 预算控制多候选生成（`agents/solver.py`）→ 一致性投票/续写/critic/repair（`tools/vote.py`、`agents/critic.py`）等工程。

## 4. 对本项目的启示与提醒

1. **112 表可直接核验**：`math_agent_official_golds_112.csv` 含全部题面+gold，可与你平台遇到的 112 题逐题对照，估算该队"查表覆盖率"。若题面逐字一致则命中即满分——这也解释了此类版本"高且稳"的原因（确定性成分，非模型能力）。
2. **口径卡可全文检索**：ICMA/math_agent 卡清单 md 中保留了每张卡的"检索词/命中条件/判分答案/错值警示"，可 grep 关键词判断是否覆盖你在做的题。
3. 诚实提醒：112 表注释表明其来自"评测包"回灌，口径卡是按判分/评委反馈逆向写死——**这类"答案/判分口径预置"成分若直接搬上平台，有评测公平性与查重/审计风险**；分析理解用于改进自家验证-精炼流程（如"错值警示"思想可借鉴为验证器的反例清单）是合规且有价值的。
4. 三个仓库的实际能力边界：math_agent = 表命中满分 + miss 走推理；ICMA = 卡命中高分 + RAG 参考 + 多代理；ss = 无捷径的纯推理工程（其分数更能代表"流程本身"的真实水位）。
