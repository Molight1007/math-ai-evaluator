# MathPilot Agent 优化计划 v2

> 基于 2026-07-28 项目最新代码状态制定，包含 6 大优化模块，预估提升准确率 8-15%。

---

## 一、当前项目状态总结

### 已有的核心能力
- **完整流水线**：分类(18领域) → 求解(蓝图/普通) → 验证(多轮投票) → 调控(自纠错回环) → 格式化
- **评测生态**：GUI + CLI + Web 三入口，支持 6 种文件格式自动转化，HTML/JSON/CSV 多格式报告
- **Lean 4 形式化验证**：四阶段流水线（转化→编译→错误分析→修正），含 AND-OR DAG 蓝图可视化
- **Web 服务**：FastAPI + 纯前端，用户系统(JWT+审批)、题库管理、WebSocket 实时推送

### 关键发现
1. **Solver 所有候选用相同温度**，缺乏多样性——这是影响上限的核心瓶颈
2. **Verifier 只有 A/B 二元判定**，无法区分"格式错但逻辑对"和"完全错误"
3. **无快速通道**，即使是纯算术题也走完整 LLM 流水线
4. **答案提取后无规范化**，LaTeX 变体、隐式乘法等差异导致比较困难
5. **无 wall-clock 超时保护**，单题可能卡死
6. **无幻觉检测**，模型伪造 output 块、42 兜底答案等不会被捕获

## 二、6 大优化模块

### 模块 1：安全防护层（`base.py` + `solver.py`）
**目标**：防止单题卡死，过滤模型幻觉输出

| 功能 | 改动位置 | 思路 |
|------|---------|------|
| **wall-clock 超时** | `base.py` 新增 `TimedContext` 上下文管理器 | 每次 LLM 调用包裹 `threading.Timer`，超时抛异常并被 `_fallback` 捕获 |
| **超时回溯** | `solver.py` 的 LLM 调用包装 | 超时发生时，从已生成的部分答案中回溯提取最优结果，而非丢弃 |
| **幻觉模式检测** | `solver.py` 新增 `_detect_hallucination(raw_text)` | 检测空响应、连续重复token、42 魔法数字、伪造的 `output` 块标记 |
| **截断恢复** | `solver.py` 新增 `_repair_truncated(response)` | 检测并修复被 `max_tokens` 截断的不完整代码块（缺失闭合括号等） |

**预期收益**：漏洞率降低 3-5%，极端题目不拖慢整体评测。

---

### 模块 2：三段式验证升级（`verifier.py` + 新增 `utils/equiv.py`）
**目标**：从简单 A/B 投票升级为结构化多维评分

```
原流程：LLM投票(3次) → A/B → 取多数 → 算confidence

新流程：
  规则预筛 → 等价分组 → LLM多维评分 → 加权综合
```

#### 2.1 规则预筛（纯规则，零 LLM 开销）
- 空答案/乱码 → 直接标记为错误
- 不含任何数字/数学表达式的文本回答 → 直接标记为错误
- 格式明显不符合题意的（如要求数值给了文字描述）→ 直接标记为错误

#### 2.2 等价分组（基于 SymPy）
- 将多个候选按数学等价性分组
- 同一组内的答案虽然字符串不同，但数学上等价（如 `3/2` 和 `1.5` 和 `1\frac{1}{2}`）
- 分组结果用于后续 LLM 评分的权重调整

#### 2.3 LLM 多维评分
修改 `prompts/verifier.py`，让 LLM 按 4 个维度评分（1-5 分制）：

| 维度 | 权重 | 说明 |
|------|------|------|
| 答案格式 | 15% | 是否符合题目要求的输出格式 |
| 数值正确性 | 40% | 最终答案是否在数学上正确 |
| 逻辑完整性 | 30% | 推理链是否连贯、关键步骤是否缺失 |
| 表达清晰度 | 15% | LaTeX 格式是否正确、推理是否通顺 |

Verifier 输出从 `A/B` 改为 JSON：
```json
{
  "overall": "A",
  "scores": {"format": 5, "correctness": 4, "logic": 3, "clarity": 4},
  "reason": "..."
}
```

权重公式：`final_score = Σ(dimension_score × weight) / 5`
confidence 不再用简单票数比，而是用加权分数映射。

**预期收益**：假阳性减少 5-8%，验证更精准。

### 模块 3：候选多样性增强（`solver.py` + `config.py`）
**目标**：让多候选之间真正有差异，而非重复生成相似推理

#### 3.1 温度分层
候选 1：temperature = 0.1（稳定保守）
候选 2：temperature = 0.3（平衡）
候选 3：temperature = 0.5（探索性强）

**触发条件**：`config.num_candidates >= 3` 时自动启用，少于 3 个则均匀分布。

#### 3.2 候选数量自适应
根据题目难度和领域决定生成几个候选：

| 领域 | 默认候选数 | 理由 |
|------|-----------|------|
| 证明题 | 1 | 多条推理链难以比较，且 LLM 对证明题一致性高 |
| 单选题/填空题 | 3 | 需要多样性来互相验证 |
| 计算题（高难度标记）| 3-5 | 数值计算容易有细微差异，多候选可交叉验证 |

难度判断依据：classifier 输出的领域 + 题目长度 + 是否含复杂数学表达式。

#### 3.3 提示词微扰
在不改变温度的情况下，给不同候选的 system prompt 加入细微差异：
- 候选 1：标准提示词
- 候选 2：末尾追加"请特别注意计算过程中的细节" 
- 候选 3：末尾追加"可以用不同的方法重新审视这个问题"

**预期收益**：多候选场景准确率提升 5-10%。

---

### 模块 4：答案后处理管道（`extract.py` + `formatter.py`）
**目标**：让提取出的答案在不同格式下可精确比较

#### 4.1 答案规范化管道（`extract.py` 新增 `normalize_answer()`）
6 步清理管道，按顺序执行：

| 步骤 | 处理内容 | 示例 |
|------|---------|------|
| 1. LaTeX 归一化 | `\frac{a}{b}` → `a/b`，`\sqrt{n}` → `sqrt(n)` | 统一不同 LaTeX 写法 |
| 2. 隐式乘法补全 | `2x` → `2*x`，`(x+1)(x-1)` → `(x+1)*(x-1)` | 让表达式可计算 |
| 3. 空白与标点清洗 | 移除多余空格、中文/英文混用标点 | `"答案是：3"` → `"3"` |
| 4. 数值格式统一 | `1/2` → `0.5`，`2.0` → `2` | 分数→小数，整数去尾零 |
| 5. 单位剥离 | `3 cm`, `3cm`, `3厘米` → `3` | 统一单位表述 |
| 6. 集合/区间格式 | `{1,2,3}`, `[1,3]`, `(1,3]` 标准化 | 统一分隔符和括号样式 |

#### 4.2 答案终检 + 自动修复（`formatter.py` 新增 `_diagnose_and_repair()`）
在 formatter 选择最佳答案后、输出前，再加一层检查：

| 检测项 | 检测方式 | 修复策略 |
|--------|---------|---------|
| 空答案 | 直接判断 | 从其他候选中选取非空答案 |
| 42 幻觉 | 匹配 `42` 或 `42.0` 孤立的模式 | 标记为可疑，降低置信度 |
| 截断 LaTeX | 检测未闭合的 `$`、`{`、`\[` | 尝试补全或回退到上一个完整表达式 |
| markdown 污染 | `**3**`、`_5_` 等格式标记残留 | 剥离 markdown 语法 |
| 多余文字包裹 | `因此答案是 42。综上所述` | 重新调用 extract 提取核心答案 |

**预期收益**：格式化错误率降低 8-12%。

### 模块 5：快速通道（`orchestrator.py` 新增 `_fast_path()`）
**目标**：对可确定性求解的题目跳过 LLM 流水线

#### 5.1 预检逻辑
在 classifier 之前，用正则快速判断题型：

```python
FAST_PATH_PATTERNS = {
    "simple_arithmetic": r"^\d+[\+\-\*/]\d+$",         # 3+5
    "polynomial_derivative": r"求导.*[xy]\^?\d*",       # 求导 x^2
    "definite_integral": r"积分|∫.*dx",                  # ∫x dx
    "matrix_determinant": r"行列式|det",                  # det(A)
    "linear_equation": r"解(方程|方程组)",                # 解方程
    "quadratic": r"一元二次|二次方程|x\^2",              # x^2+3x+2=0
}
```

匹配成功 → 用 SymPy 直接计算 → 返回结果，跳过完整流水线。

#### 5.2 降级策略
SymPy 计算超时（>5秒）或抛异常 → 回退到正常 LLM 流水线，无惩罚。

**预期收益**：简单题零成本零幻觉，节省的 LLM 预算可用于难题更多候选。

### 模块 6：代码结构优化
**目标**：降低维护成本，减少 bug 引入风险

| 优化项 | 具体操作 | 优先级 |
|--------|---------|--------|
| `lean_verifier.py` 拆分 | 拆为 `lean_converter.py` + `lean_compiler.py` + `lean_analyzer.py` | 中 |
| `reporter.py` HTML 分离 | HTML 模板提取为独立 `.html` 文件 | 低 |
| `_run_inference_func` 全局变量 | 改为配置驱动或依赖注入 | 中 |
| 硬编码字符串国际化 | 提取为 `i18n.py` 常量文件 | 低 |
| Lean 默认超时 | `_DEFAULT_LEAN_TIMEOUT` 从 0(无限制)改为 30s | **高** |
| 重复 HTML 转义逻辑 | 统一使用 `utils.escape_html()`，删除 `reporter.py` 中的副本 | 中 |
| JWT Secret 警告 | 启动时检测默认值并打印警告 | 中 |

## 三、分阶段执行顺序

### 第一阶段（核心提升，2-3h）
1. ✅ **安全防护层** — wall-clock 超时 + 幻觉检测（最基础，影响所有题目）
2. ✅ **候选多样性增强** — 温度分层 + 数量自适应（直接提升准确率）

### 第二阶段（质量深化，3-4h）
3. ✅ **三段式验证升级** — 规则预筛 + 等价分组 + LLM 多维评分
4. ✅ **答案后处理管道** — 规范化 + 终检修复

### 第三阶段（效率优化 + 收尾，2-3h）
5. ✅ **快速通道** — SymPy 预检（需安装 sympy，pip install sympy）
6. ✅ **代码结构优化** — 安全修复 + 模块拆分
7. ✅ **全量代码审核** — linter 检查 + 逻辑审核 + 回归测试

## 四、风险与回退策略

| 风险 | 缓解措施 |
|------|---------|
| 新功能引入 bug | 所有功能通过 config 开关控制，默认关闭，逐个启用验证 |
| SymPy 依赖增加复杂度 | 快速通道独立模块，失败自动回退，不影响现有流程 |
| 三段式验证增加 LLM 调用 | 规则预筛先砍掉明显错误的答案，减少实际 LLM 调用次数 |
| 代码拆分导致导入错误 | 保留原文件作为兼容层，新模块独立引入 |
