## 二、今日修掉的一个真 bug（重要，避免复现）

- 诊断：`python run.py --check` 会脱敏打印实际生效的 key，一眼看出是否被遮住。
- 复核证据：用 `.env` 中的 key 直连 API 返回 `"2"`，正常。

## 三、科学问题 → 操作化定义（论文的骨架）

| 老师的问题 | 本项目的操作化定义 | 对应探针 |
|---|---|---|
| "它有否联想的功能" | 见过结构同构的源题后，能否把方法迁移到**表层不同**的目标题 | **A 同构迁移** |
| "能否观察到更本质的数学结构" | 解完题后能否**命名**结构；给定结构名能否**构造**出体现它的最小证明 | **C 结构指认**（正向 + 反向） |
| "不能因短板忽视它可能没呈现的长板" | 设计能**捕捉到**结构洞察的实验，而非只记录失败 | C 的反向任务、D 的参数化抽象 |
| （延伸）类比会不会用错地方 | 表层像模板 X、实则需要 Y 时是否会被骗 | **B 陷阱题** |
| （延伸）抽象能力 | 具体⇄一般的双向映射 | **D 抽象⇄实例化** |

### 方法创新点（论文卖点）

> **证明结构指纹**：一个证明用了哪些 tactic / 引理 == 它走的是哪条"结构路径"。

过去测"模型是否理解结构"只能靠人读答案打分——主观、不可规模化、不可复现。
本项目把它变成两个集合的重合度：

- **核心迁移率** = 目标题指纹 ∩ 共享结构核心 ÷ 共享结构核心
- **方法继承率** = 目标题指纹 ∩ 源题指纹 ÷ 源题指纹

并且**判据是 Lean 编译器，不是 LLM 自评**——这是相对"选择题自评"类工作的根本区别。

### ⚠️ 必须正视的能力边界

**Mathlib 闭包只有 `Mathlib.Tactic`，不含 BigOperators 的 `∑` 记号**

推论：**Lean 客观判据天然偏向代数 / 数论题，组合与几何题很难低成本形式化**。
这是本方法最大的覆盖面限制，必须在论文 limitations 里写清楚，并在 §五 阶段 1 针对性补设计。

## 七、论文大纲（建议）

1. **引言** —— 大模型数学推理"能做对题"与"是否理解结构"之间的鸿沟
2. **相关工作** —— 数学推理基准、形式化验证辅助求解、LLM 自评的不可靠性
3. **方法**
   - 3.1 证明结构指纹：把"方法迁移"变成可计算的连续量
   - 3.2 四类思想实验探针的设计原理（同构 / 陷阱 / 指认 / 抽象）
   - 3.3 以 Lean 编译器为客观判据（区别于 LLM 自评）
4. **实验设置** —— 题库、结构标注、模型、人类对照组
5. **结果** —— 核心迁移率、陷阱识破率、指认准确率 vs 反向构造率、多模型对比
6. **失败模式分析** —— 模型在哪个环节丢失结构
7. **讨论** —— LLM 是否具备联想能力；能否观察本质数学结构
8. **局限与展望** —— 组合/几何形式化覆盖不足、标注主观性、模型迭代快

**可能的 headline 结论**（待数据验证）：
若结果显示「题目能解对，但核心迁移率低」，则结论是
**大模型擅长模式匹配、弱于结构迁移** —— 这正是对老师那个问题的定量回答。
