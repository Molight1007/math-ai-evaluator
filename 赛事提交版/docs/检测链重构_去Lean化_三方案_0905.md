## 0. 背景：为什么 sq 分支平台分更高（一句话）

sq 分支是"非 Lean 轻量路线"（`enable_lean_verify=False`），检测全靠 **Verifier + SymPy 确定性
旁证**（0 LLM 预算、无外部二进制依赖）→ 平台全程有效；而当前线（3569d53）把"客观审核"押在
Lean 上，平台无 Lean → preverify / lean_filter / lean_gate / oracle.verify_proof **全部 unknown
空转**，只付时间不审核 → 单题撞 1200s 墙 → 56 invalid + 答出题的审核链形同虚设。

方向：把客观审核从 Lean 迁移到「SymPy 确定性 + LLM 结构化判分（rubric）+ 程序化反例挑战」，
复用 sq 已验证的检测资产；Lean 系代码整体移出 agent 运行时（本地证据链/材料另行保留）。

**当前检测链 vs sq 检测链（检测位对照）**

| 检测位 | 当前 3569d53 | sq 分支 | 说明 |
|---|---|---|---|
| 题前理解确认 | 2.6 preverify（Lean 形式化编译） | 无（轻量） | 平台空转 |
| 候选客观过滤 | 3.5.1 lean_candidate / 3.6 lean_filter（Lean） | 无（交投票） | 平台空转 |
| 主投票 | 4 verifier（A/B + 确定性硬否决 v2.8） | verifier（A/B + **rubric + 挑战**） | sq 多 rubric/反例 |
| 客观复核 | 4.5 oracle（证明走 Lean，计算走 SymPy） | 无 | oracle 证明位空转 |
| 证伪 | 4.6 adversarial（LLM 对抗） | 无 | 同型 |
| 最终闸门 | 6.5 lean_gate（Lean 硬验证 + rework 循环） | 无（投票共识即出） | 平台空转 |
| 答案等价匹配 | verifier._are_answers_equivalent | 同 + local answers_match v2 | — |

## 方案一：移植 sq 的 Verifier 检测逻辑（agent 检测链增强）

### 1.1 移植哪些（sq 独有、当前缺失、且有正证据的）

| 资产 | sq 实现 | 证据 | 是否移植 |
|---|---|---|---|
| **A. rubric 结构化判分** | `_vote_one_rubric`：JSON prefill 秒回 `{verdict, confidence, error_type, step_index, reason}`，借鉴 Intern-MO judge | 检测错因质量是最大杠杆（IMO2025 验证-精炼 85.7%；当前推理错误占 63% 主因是 revise 无定向错因） | ✅ 移植（默认关，A/B 后开） |
| **B. 反例挑战** | `_challenge_counterexample`：LLM 生成命题 → `DeterministicChecker.search_counterexample`（300 attempts）程序数值验证 → hard_fail 硬否决 | 非数值答案的客观证伪通道；比 4.6 纯 LLM 对抗多一层"程序验证反例"，误报低 | ✅ 移植（默认关） |
| **C. 确定性旁证硬否决语义** | `_vote_rubric`：det fail→硬否决；det pass→**追加独立正确票**；unknown→只挂证据 | 当前 4_verify 只有 fail→判错 + 全 fail 回退，缺 pass→独立票 | ✅ 语义补齐 |
| D. verify 提示加强（候选代入验证，借鉴 AIMO） | fbe374a | **平台 23.21→21.43 掉分，已回滚（e4babb1）** | ❌ **排除**（有平台负证据） |

### 1.2 改动范围

| 文件 | 改动 |
|---|---|
| `prompts/verifier.py` | 新增 `VERIFIER_RUBRIC_SYSTEM/TEMPLATE`、`VERIFIER_CHALLENGE_SYSTEM/TEMPLATE`（自 sq 移植并适配当前模板格式） |
| `agent/verifier.py` | 新增 `_vote_one_rubric/_parse_rubric_json/_vote_rubric`、`_challenge_counterexample`（复用 `_get_checker().search_counterexample`）；`run()` 增加 `use_rubric/use_challenge` 参数与执行分支；deterministic pass → 追加 `deterministic_pass` 独立正确票 |
| `agent/deterministic.py` | 核对 `search_counterexample` attempts 上限（sq 300 vs 当前 200）与 statement 解析覆盖，必要时补参数 |
| `agent/orchestrator.py` | 4_verify 调用传 `use_rubric=config.use_rubric, use_challenge=config.use_challenge`；challenge 仅对"全错票候选"触发（sq 语义）；rubric 与 4.6 adversarial 并存（见方案二职责划分） |
| `user_agent.py` | `AgentConfig` 增加 `use_rubric: bool = False`、`use_challenge: bool = False`（进 overrides 白名单） |
| `tests/` | 新增 rubric 解析/挑战触发/确定性 pass 独立票的确定性单测 |

### 1.3 替换前后检测行为差异

| 维度 | 替换前（当前） | 替换后 |
|---|---|---|
| 投票输出 | A/B 二元，无错因 | rubric 时输出 verdict+confidence+**error_type+step_index+reason** |
| 非数值答案证伪 | 仅 4.6 LLM 对抗（同源自评，有漏检） | + LLM 命题 → **SymPy 程序数值验证**反例（客观，误报低） |
| 确定性旁证 | fail→判错；pass 只挂证据 | fail→判错；**pass→追加独立正确票**（非 LLM 客观票） |
| revise 反馈 | 通用"请重新审题"或 bugreport | rubric 错因（步骤定位）→ 定向修正 |
| LLM 调用增量 | — | rubric 每候选 1 次 JSON prefill（秒级）+ challenge 仅全错候选 1 次 |

### 1.4 预期效果
- 检测错因质量↑ → revise 定向性↑ → 答出题正确率↑（本地目标：45 题基准从 35.6% 组合再 +3pp 级）
- 挑战/确定性提供"非 LLM 客观票"，降低验证器与解题器同源共错的假阳性放行
- 成本：rubric JSON prefill 约秒级（prefill 抑制 CoT），挑战仅失败候选触发，预算增量可控
- ⚠ 验收纪律：先本地 30/45 题 A/B（配对判定 net≥3 且 a≥2b 才开；只信 ≥5pp）；rubric/challenge 单点增益不足则保持默认关

## 方案二：新审核模块取代 Lean（平台去 Lean 化）

### 2.1 新模块：AuditGate（答案审核闸门）——职责边界

取代 lean_gate / lean_pre_verifier / oracle.verify_proof 在检测链中的全部作用。

**职责（只审不答）**：对候选解答与最终答案做客观/结构化审核 → 产出可消费的裁决
（verdict / confidence / error_type / step_index / reason / suggestion）。
**不做**：不生成答案、不改写题目、不做规划/子目标、不产出 Lean 代码。

### 2.2 审核流程（多级瀑布，0→3 严格递减）

```
Level 0  程序硬核验（0 LLM）：deterministic.check_answer
         └ 把答案代回题干等式数值回验（_verify_answer_in_equation /
           verify_by_substitution）→ fail 即硬否决
Level 1  程序反例/扫描（0 LLM）：search_counterexample（LLM 已命题则验）
Level 2  LLM rubric 判分（JSON prefill 秒回）：verdict+confidence+error_type+step_index
         （证明题：逐步骤审核 PROOF_VERIFY 路径，保留 step findings）
Level 3  独立重算一致性：playoff（低温重解对比，deep+时间宽裕）
裁决合成：Level0/1 硬否决优先；否则 rubric/步骤审核票并入投票共识（verifier.cluster）；
全 unknown/全 fail 时回退保留（宁 unknown 不误杀——沿用 lean_gate 降级哲学）。
```

### 2.3 输入输出接口（与现有检测模块衔接）

```python
class AuditGate:
    def audit_candidates(self, ctx, candidates, tier, is_proof) -> dict:
        """候选审核（顶替 3.6 lean_filter 位）。返回 {verdicts, feedbacks, kept}：
        verdicts 为每候选追加的 AuditVerdict（correct/incorrect/unknown + 错因），
        供 verifier 聚类并入；feedbacks 注入 revise_feedback。"""
    def gate_final_answer(self, ctx, tier) -> tuple[bool, str]:
        """最终答案闸门（顶替 6.5 lean_gate 位）。返回 (ok, feedback)；
        ok=False 时 orchestrator 沿用现有 rework 循环（按档封顶 ≤2/deep 到墙、
        剩余 <35s 停、重生成需剩 ≥180s）换候选或重做。"""
    def confirm_understanding(self, ctx) -> dict:
        """题前理解确认（顶替 2.6 preverify 位，可选）：LLM 复述题意+题型+未知量
        类型确认，失败注入 revise_feedback（不阻断）。"""
```

**衔接点（orchestrator 改动）**：

| 现调用点（行号区） | 现行 | 改为 |

| 3.5.1_lean_candidate（~571-576） | `_lean_verify_top_candidates` | **删除**（Lean verify top2 无 lean 空转） |
